JHS 2 Computing

Problem Solving

Use logic, algorithms and step-by-step thinking to solve complex digital tasks.

Key idea

Breaking problems into smaller steps and following clear logic makes solutions work correctly.

Understanding the Problem

Before solving, understand what you need to accomplish. Identify inputs (what you start with), outputs (what you need to produce), and constraints (limitations or rules).

Problem: Create a program to sort students by grade. Input: list of student names and grades. Output: students arranged from highest to lowest grade. Constraint: alphabetical order if grades are equal.

Decomposition: Breaking Problems Into Parts

Large problems are easier to solve if broken into smaller pieces. Each piece should have a clear purpose and produce output that the next piece uses as input.

Large problem: "Build a game." Smaller parts: create characters, define movement rules, set winning conditions, create menus.

Algorithms and Flowcharts

An algorithm is a sequence of clear steps to solve a problem. A flowchart shows these steps visually with shapes: rectangles for actions, diamonds for decisions, arrows showing flow.

Good algorithms are unambiguous, complete, efficient and tested.

Debugging: Finding and Fixing Errors

Debugging is systematic error-finding. Test your solution with different inputs. If results are wrong, trace through the steps to find where the logic fails. Make small changes and test again.

If a sorting program produces the wrong order, check the comparison logic. Are you comparing correctly? Are you moving items correctly?

Optimisation: Making Solutions Better

After your solution works, make it faster, use less memory or be easier to understand. Sometimes a simpler approach works better than a complex one.

Quick Check

Why is breaking a problem into smaller parts helpful?

Smaller parts are easier to understand, solve and test. Each part can be worked on independently.
